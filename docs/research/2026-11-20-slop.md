# Research: preventing slop in code and documents

Date: 2026-11-20. One researcher agent; abstracts and summaries, marked where unverified.

## Summary

Agents add more than they remove and drift past scope. Measured: copy-pasted lines rose from 8.3% to 12.3% of changes (2020 to 2024) while refactored lines fell from about 25% to under 10% (GitClear 2025, correlational, vendor); Cursor adoption brought a lasting rise in static-analysis warnings and complexity (arXiv 2511.04427); in iterative refactoring every model kept editing, up to 31x the codebase (arXiv 2610.36346); bigger agent PRs carry more issues (arXiv 2601.20109). No study shows that an instruction like "do not over-engineer" reduces slop. Gates do what instructions do not.

## What Scriptorium should do

- Documents: a banned-phrase list per document type (from Wikipedia's "Signs of AI writing": "pivotal", "delve", "serves as", "not just X but Y", "seamless"...), with an explicit inline exemption; line caps per document and section; a duplication gate between documents (a downstream document links upstream ids, never copies their text); empty or filler sections fail ("TBD", "n/a" without a reason, a section that restates its heading); every id, path and symbol a document cites must exist.
- Code: unused-code detection (knip for TypeScript) and duplication detection (jscpd with a threshold set from the current baseline and only lowered); a diff-size warning against the FRD's scope, with a stated reason when additions far exceed deletions.
- Review: one closed criterion, "nothing beyond the FRD", since agents drift past scope.
- Agent files: short, only non-standard practices, no repository overviews (arXiv 2602.11988).
